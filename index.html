Part 1
Flashing OpenWrt on the ER605

Replace TP-Link's stock firmware with OpenWrt. This section is specific to the ER605 v2 hardware.

Overview

This guide covers replacing the stock TP-Link firmware on the ER605 v2 with OpenWrt. It applies to all hardware revisions (V2.0, V2.20, V2.26, V2.60) — the limiting factor is the firmware version, not the hardware revision.

Based on chill1Penguin's method. The password generator, backup scripts, and initramfs image come from that project.

⚠

Do NOT connect to the internet

Keep the WAN cable disconnected during the entire flashing process. If the router detects internet access, TP-Link requires an online-signed token and the locally generated password stops working.

⚠

No factory recovery after flashing

After flashing OpenWrt, the ER605's Emergency Recovery Mode is disabled. The only way back to stock firmware is via ubiformat from OpenWrt's console using your MTD backup.

⚠

Bricking risk

If power is lost during flashing, the router may be permanently bricked. Use a stable power source and don't disconnect anything during the process.

Firmware Compatibility

The hardware revision (V2.0, V2.20, etc.) does NOT matter. Only the firmware version matters.

Firmware Status Root Access Method
≤ 2.0.1 ✅ Works Direct root login with "root password"
2.1.1 – 2.2.5 ✅ Works GUI login + enable + debug + CLI debug password
2.2.6 ❌ Blocked Local password generator patched out
2.3.0 – 2.3.3 ❌ Blocked RSA-signed tokens + anti-rollback. Downgrade impossible.

Firmware 2.2.6+ is confirmed blocked. Tested live in March 2026: downgrade from 2.3.3 to 2.2.5 was impossible using Emergency Recovery, GUI rollback, SSH rollback, and factory reset. If your router already has 2.2.6+, your options are: contact TP-Link support, buy another ER605 with 2.2.5, or wait for a community bypass.

1b-bis. Create the flashing script (recommended: safer version)

Instead of downloading chill1Penguin's original script, we create a hardened, 100% POSIX rewrite locally. It does the same thing — flash the initramfs to both kernel UBI partitions — but adds input validation, size bounds (1–5 MiB: catches HTML error pages on the small side and oversized images like a sysupgrade .bin on the large side), a check that ubiupdatevol is actually present (so you can't run it on the wrong machine by accident), proper quoting, set -eu, validation of volumes_count, a read-back verification of every write (reads each volume back and compares it byte-for-byte with cmp, so a flash that silently landed wrong is caught now instead of at next boot), a power-loss warning (use a UPS, stay wired, don't unplug mid-flash), an explicit confirmation prompt, and explicit error messages tailored to which flash failed: if the first flash fails, kernel.b is still intact and the router can still boot — safe to retry. If the second flash fails, the script tells you NOT to reboot until you re-run it.

Paste the whole block below into your terminal — it writes the script with a heredoc and makes it executable:

cat > er605v2_write_initramfs.sh <<'EOF'
#!/bin/sh
#
# er605v2_write_initramfs.sh — safer POSIX rewrite of chill1Penguin's
# original script. Flashes an OpenWrt initramfs image to BOTH kernel
# UBI volumes (kernel and kernel.b) on the TP-Link ER605 v2.
#
# Differences vs. the original:
#   - 100% POSIX shell. No bash-isms, no backticks, no `expr`.
#   - `set -eu` aborts on any error or unset variable.
#   - Validates the input file: exists, is a regular readable file,
#     non-empty, between 1 MiB and 5 MiB (catches HTML error pages,
#     partial downloads, and oversized images that wouldn't fit in
#     the 5 MiB kernel UBI volume — e.g. a sysupgrade .bin by mistake).
#   - Sanity-checks the image magic: OpenWrt MT7621 kernel images are
#     FIT images starting with 0xD00DFEED. A mismatch only warns (a
#     custom non-FIT image is unusual but not necessarily wrong), so a
#     legitimate edge case is never hard-blocked.
#   - All variables are quoted (handles paths with spaces).
#   - Validates that volumes_count is a positive integer.
#   - Shows a summary and asks for an explicit "yes" before flashing.
#     Skip with: SKIP_CONFIRM=1 ./er605v2_write_initramfs.sh image.bin
#   - VERIFIES each write by reading the volume back and comparing it
#     byte-for-byte against the image (cmp). The kernel volumes are
#     static UBI volumes, so a successful read-back also re-checks UBI's
#     own CRC-32. A flash that "succeeded" but didn't land correctly is
#     caught here instead of at the next boot. If the stock firmware's
#     busybox lacks cmp, verification is skipped with a notice (it is
#     never misreported as a failure); ubiupdatevol's CRC still guards
#     the boot.
#   - Both ubiupdatevol calls are explicitly checked. If the FIRST
#     fails (or fails verification), the second partition is untouched,
#     so the router can still boot — safe to retry. If the SECOND fails
#     after the first succeeded, the script exits non-zero with a clear
#     message so you know NOT to reboot before retrying the kernel.b
#     flash.
#   - Calls sync on every exit path that touched the flash.
#
# Usage: ./er605v2_write_initramfs.sh openwrt-initramfs-compact.bin

set -eu

SCRIPT_NAME=$(basename "$0")
MIN_SIZE=1048576    # 1 MiB  — below this is almost certainly an error page
MAX_SIZE=5242880    # 5 MiB  — kernel UBI volume size; larger won't fit

if [ $# -ne 1 ]; then
    echo "USAGE: $SCRIPT_NAME <path to openwrt-initramfs.bin>" >&2
    echo "EXAMPLE: ./$SCRIPT_NAME openwrt-initramfs-compact.bin" >&2
    exit 1
fi

IMAGE=$1

# ---- 1. Validate the input file ---------------------------------------
if [ ! -e "$IMAGE" ]; then
    echo "ERROR: '$IMAGE' does not exist." >&2
    exit 1
fi
if [ ! -f "$IMAGE" ]; then
    echo "ERROR: '$IMAGE' is not a regular file." >&2
    exit 1
fi
if [ ! -r "$IMAGE" ]; then
    echo "ERROR: '$IMAGE' is not readable." >&2
    exit 1
fi
if [ ! -s "$IMAGE" ]; then
    echo "ERROR: '$IMAGE' is empty." >&2
    exit 1
fi

IMAGE_SIZE=$(wc -c < "$IMAGE")
if [ "$IMAGE_SIZE" -lt "$MIN_SIZE" ]; then
    echo "ERROR: '$IMAGE' is only $IMAGE_SIZE bytes -- too small to be a" >&2
    echo "       real initramfs image (expected >= $MIN_SIZE bytes)."    >&2
    echo "       Did the download fail or return an HTML error page?"    >&2
    exit 1
fi
if [ "$IMAGE_SIZE" -gt "$MAX_SIZE" ]; then
    echo "ERROR: '$IMAGE' is $IMAGE_SIZE bytes -- too large for the"      >&2
    echo "       kernel UBI volume (max $MAX_SIZE bytes / 5 MiB)."        >&2
    echo "       Did you pass a sysupgrade .bin instead of the initramfs?" >&2
    exit 1
fi

# ---- 1b. Sanity-check the image magic (warn-only) ---------------------
# OpenWrt MT7621 kernel images are FIT images: the first 4 bytes are the
# device-tree blob magic 0xD00DFEED. We read exactly 4 bytes with dd (so we
# never depend on od's -N flag, which some stripped busybox builds omit; a
# bare `od` on a 3 MiB file would otherwise dump the whole image into this
# variable) and only WARN on mismatch — a hand-built non-FIT image is unusual
# but might be legitimate, and hard-blocking it would push you toward the
# less-careful original script. The size check above already catches the
# common mistakes.
MAGIC=$(dd if="$IMAGE" bs=1 count=4 2>/dev/null | od -An -tx1 | tr -d ' \n')
if [ "$MAGIC" != "d00dfeed" ]; then
    echo "WARNING: '$IMAGE' does not start with the expected FIT magic"   >&2
    echo "         (0xD00DFEED). Got: 0x$MAGIC."                          >&2
    echo "         This is the right magic for a stock OpenWrt MT7621"    >&2
    echo "         initramfs. If you built a custom image you may know"   >&2
    echo "         better; otherwise double-check you have the right file." >&2
fi

# ---- 2. Check that ubiupdatevol is available --------------------------
if ! command -v ubiupdatevol >/dev/null 2>&1; then
    echo "ERROR: 'ubiupdatevol' not found in PATH."                  >&2
    echo "       Are you running this on the ER605 (not on your PC)?" >&2
    exit 1
fi

# ---- 2b. Is cmp available for read-back verification? -----------------
# The stock TP-Link firmware runs a stripped busybox that may not ship cmp.
# If it's missing we SKIP the byte-for-byte read-back (with a clear notice)
# instead of misreporting a successful flash as a failure. The flash itself
# is unaffected: ubiupdatevol writes a CRC-32 into the static kernel volume
# that UBI re-checks on every read and at boot.
CAN_VERIFY=1
if ! command -v cmp >/dev/null 2>&1; then
    CAN_VERIFY=0
fi

# ---- 3. Locate the UBI volumes ----------------------------------------
if [ ! -r /sys/class/ubi/ubi0/volumes_count ]; then
    echo "ERROR: /sys/class/ubi/ubi0 not found. Is UBI attached?" >&2
    exit 1
fi

VOL_COUNT=$(cat /sys/class/ubi/ubi0/volumes_count)
case $VOL_COUNT in
    ''|*[!0-9]*)
        echo "ERROR: unexpected volumes_count value: '$VOL_COUNT'" >&2
        exit 1 ;;
esac
if [ "$VOL_COUNT" -lt 1 ]; then
    echo "ERROR: ubi0 reports zero volumes." >&2
    exit 1
fi

VOL_KERNEL=
VOL_KERNELB=

i=0
while [ "$i" -lt "$VOL_COUNT" ]; do
    if [ -r "/sys/class/ubi/ubi0_$i/name" ]; then
        NAME=$(cat "/sys/class/ubi/ubi0_$i/name")
        case "$NAME" in
            kernel)   VOL_KERNEL=$i ;;
            kernel.b) VOL_KERNELB=$i ;;
        esac
    fi
    i=$((i + 1))
done

if [ -z "$VOL_KERNEL" ] || [ -z "$VOL_KERNELB" ]; then
    echo "ERROR: required UBI volume not found (need 'kernel' and 'kernel.b')." >&2
    exit 1
fi

# ---- 4. Show summary and confirm --------------------------------------
echo "========================================================"
echo " ER605 v2 -- initramfs flash"
echo "--------------------------------------------------------"
echo " Image:         $IMAGE"
echo " Image size:    $IMAGE_SIZE bytes"
echo " Will flash to: /dev/ubi0_$VOL_KERNEL  (kernel)"
echo "                /dev/ubi0_$VOL_KERNELB  (kernel.b)"
echo "========================================================"
echo
echo " WARNING: this OVERWRITES both kernel partitions."
echo " A power loss during flashing can BRICK the router."
echo
echo " Before you continue:"
echo "   * Use a stable power source (UPS if you have one)."
echo "   * Do NOT unplug the router or your machine mid-flash."
echo "   * Run this over a WIRED connection (or serial console),"
echo "     never over Wi-Fi — a dropped link mid-write is dangerous."
echo "   * The whole flash takes only a few seconds; let it finish."
echo

if [ "${SKIP_CONFIRM:-0}" != "1" ]; then
    printf "Type 'yes' to continue: "
    ANSWER=
    read -r ANSWER || true
    if [ "$ANSWER" != "yes" ]; then
        echo "Aborted."
        exit 1
    fi
fi

# ---- 5. Flash + verify ------------------------------------------------
# Helper: read the volume back and compare it byte-for-byte to the image.
# The kernel volumes are static UBI volumes, so reading the char device
# returns exactly the written data (and re-checks UBI's CRC-32 on the way).
# If cmp isn't present on this firmware, print a notice and return success
# (0) so a missing tool is never mistaken for a corrupt flash.
verify_volume() {
    # $1 = human label, $2 = volume device path
    if [ "$CAN_VERIFY" != "1" ]; then
        echo "NOTE: 'cmp' not available -- skipping read-back verification of $1."
        return 0
    fi
    echo "Verifying $2  ($1) ..."
    cmp -s "$2" "$IMAGE"
}

# Flash kernel first. If it fails here, kernel.b is still untouched, so
# the router can still boot from kernel.b — safe to investigate and retry.
echo "Flashing /dev/ubi0_$VOL_KERNEL  (kernel) ..."
if ! ubiupdatevol "/dev/ubi0_$VOL_KERNEL" "$IMAGE"; then
    sync
    echo "ERROR: first flash (kernel) FAILED."                            >&2
    echo "       Neither partition was overwritten -- 'kernel.b' is still" >&2
    echo "       intact, so the router should still boot. Safe to retry." >&2
    exit 1
fi
sync
if ! verify_volume "kernel" "/dev/ubi0_$VOL_KERNEL"; then
    sync
    echo "ERROR: verification of 'kernel' FAILED -- the data read back"   >&2
    echo "       does not match the image. 'kernel.b' is still intact, so" >&2
    echo "       the router should still boot. Investigate and retry."     >&2
    exit 1
fi

# Flash kernel.b second. If THIS fails, kernel is already overwritten,
# so the router is in a half-updated state — must NOT reboot until
# kernel.b is also written and verified.
echo "Flashing /dev/ubi0_$VOL_KERNELB  (kernel.b) ..."
if ! ubiupdatevol "/dev/ubi0_$VOL_KERNELB" "$IMAGE"; then
    sync
    echo "ERROR: second flash (kernel.b) FAILED."                         >&2
    echo "       'kernel' was already updated. Do NOT reboot -- retry"    >&2
    echo "       the flash on /dev/ubi0_$VOL_KERNELB before rebooting."   >&2
    exit 1
fi
sync
if ! verify_volume "kernel.b" "/dev/ubi0_$VOL_KERNELB"; then
    sync
    echo "ERROR: verification of 'kernel.b' FAILED -- the data read back"  >&2
    echo "       does not match the image. 'kernel' is already updated, so" >&2
    echo "       do NOT reboot -- re-run this script to rewrite 'kernel.b'" >&2
    echo "       before rebooting."                                        >&2
    exit 1
fi

sync
echo "Done! Both kernel volumes were written and verified."
EOF
chmod +x er605v2_write_initramfs.sh

vol_count=$(cat /sys/class/ubi/ubi0/volumes_count)
vol_kernel=
vol_kernelb=

    echo "USAGE: <path to openwrt-initramfs.bin> EXAMPLE: ./er605v2_write_initramfs.sh openwrt-initramfs.bin"

name=

if [ -z $vol_kernel ] || [ -z $vol_kernelb ] ; then

   exit 1
fi

echo "Found kernel ubi partitions (ubi0_$vol_kernel and ubi0_$vol_kernelb). Flashing the initramfs.bin..."

ubiupdatevol /dev/ubi0_$vol_kernelb $1

Phase 3 — MTD Backup (strongly recommended)

6

Back up all MTD partitions

Without this backup, restoring stock firmware requires soldering a UART serial console to the PCB. Don't skip this.
Option A: Network backup with netcat (recommended)

No USB needed. Two scripts handle everything: one runs on your PC and receives the data, the other runs on the router and sends it. Partitions are streamed directly without storing anything in the router's RAM.

Step 1 — Find your PC's IP:

ip -4 addr show | grep "192.168.0"

Note the IP (e.g. 192.168.0.109). You'll need it below.

Method 1: Simple scripts (one partition per connection)

receive_backup.sh — run on your PC:

#!/bin/bash
# receive_backup.sh — Run on your PC
# Receives all MTD partitions from the ER605 via netcat

DIR=~/er605_backup
mkdir -p "$DIR"

PARTITIONS="0:Bootloader 1:Config 2:Factory 3:firmware 4:panic-oops 5:partition-table 6:support-list 7:device-info 8:device-info.b 9:tddp 10:tddp.b 11:bootloader 12:kernel 13:rootfs 14:firmware-info 15:extra-para 16:log 17:rootfs_data 18:bootloader.b 19:kernel.b 20:rootfs.b 21:firmware-info.b 22:extra-para.b 23:log.b 24:rootfs_data.b 25:log_recovery 26:database"

for PART in $PARTITIONS; do
    NUM="${PART%%:*}"
    NAME="${PART##*:}"
    FILE="$DIR/mtd${NUM}_${NAME}.bin"
    echo ""
    echo "=== Waiting for mtd${NUM} (${NAME})... ==="
    nc -l -p 9090 > "$FILE"
    SIZE=$(stat -c%s "$FILE" 2>/dev/null || echo 0)
    echo "    Received: $FILE ($SIZE bytes)"
done

echo ""
echo "=== Backup complete ==="
ls -lh "$DIR"
If nc -l -p 9090 gives an error (common on Debian/Ubuntu with OpenBSD netcat), change it to nc -l 9090 without the -p flag.

send_backup.sh — run on the router:

#!/bin/ash
# send_backup.sh — Run on the ER605 router (ash/BusyBox)
# Usage: ash send_backup.sh YOUR_PC_IP

PC_IP="$1"

if [ -z "$PC_IP" ]; then
    echo "Usage: ash send_backup.sh YOUR_PC_IP"
    exit 1
fi

i=0
while [ -e "/dev/mtd${i}ro" ]; do
    NAME=$(grep "mtd${i}:" /proc/mtd | cut -d'"' -f2)
    echo ""
    echo "=== Sending mtd${i} (${NAME})... ==="
    dd if="/dev/mtd${i}ro" | nc "$PC_IP" 9090
    echo "    mtd${i} sent."
    sleep 2
    i=$((i + 1))
done

echo ""
echo "=== All partitions sent ==="

How to use:

  1. Transfer send_backup.sh to the router via the HTTP server: curl -o /tmp/send_backup.sh http://YOUR_PC_IP:8080/send_backup.sh
  2. Run ./receive_backup.sh on your PC (it waits for each partition)
  3. Run ash /tmp/send_backup.sh YOUR_PC_IP on the router
Method 2: chill1Penguin's scripts (with auto md5sum verification)

backup.sh — paste and run on the router:

Edit BACKUP_HOST to match your PC's IP, then paste this entire block into the router's shell:

cat << "EOF" > /tmp/backup.sh
#!/bin/sh

BACKUP_HOST="192.168.0.100"  # Your PC's IP address
BACKUP_PORT="9999"            # Port to use for transfer
echo "Backup host ${BACKUP_HOST}"

echo -n > /tmp/md5sums

cat /proc/mtd | tail -n+2 | while read; do
  MTD_DEV=$(echo ${REPLY} | cut -f1 -d:)
  MTD_NAME=$(echo ${REPLY} | cut -f2 -d\")
  FILENAME="${MTD_DEV}_${MTD_NAME}.backup"

  echo "Backing up ${MTD_DEV} (${MTD_NAME})"
  # First send filename
  echo "$FILENAME" | busybox nc ${BACKUP_HOST} ${BACKUP_PORT}
  sleep 1
  # Then send the data
  dd if=/dev/${MTD_DEV}ro | busybox nc ${BACKUP_HOST} ${BACKUP_PORT}
  SUM=$(dd if=/dev/${MTD_DEV}ro | md5sum | cut -f1 -d" ")
  echo -e "$SUM\t$FILENAME" >> /tmp/md5sums
  sleep 1
done

echo md5sums | busybox nc ${BACKUP_HOST} ${BACKUP_PORT}
dd if=/tmp/md5sums | busybox nc ${BACKUP_HOST} ${BACKUP_PORT}

EOF

chmod +x /tmp/backup.sh

receive.sh — save and run on your PC:

#!/bin/bash
# receive.sh — Run on your PC
# Receives MTD backups sent by backup.sh from the router

PORT=9999
DIR=~/er605_backup
mkdir -p "$DIR"
cd "$DIR"

while true; do
  # Receive filename
  FILENAME=$(nc -l -p $PORT)
  FILENAME=$(echo "$FILENAME" | tr -d '\r\n')
  if [ -z "$FILENAME" ]; then continue; fi
  echo "Receiving ${FILENAME}..."
  # Receive file data
  nc -l -p $PORT > "$FILENAME"
done
If nc -l -p gives an error, change to nc -l without -p.

How to use:

  1. Run ./receive.sh on your PC
  2. Run /tmp/backup.sh on the router
  3. Backup takes ~5 minutes. Don't interrupt it.
  4. When done, press Ctrl+C on the PC to stop receive.sh
  5. Verify: md5sum -c md5sums

Tip: mtd3 (firmware) is the largest (~130MB) and takes ~2 minutes. The rest are small and take seconds. Store these backups somewhere safe — they're your only way back to stock firmware without a serial console.

Option B: USB backup

Format a 256MB+ USB drive as FAT32, plug it into the router, mount it, and dump all partitions.

i=0; while [ -e "/dev/mtd${i}ro" ]; do
    NAME=$(grep "mtd${i}:" /proc/mtd | cut -d'"' -f2)
    echo "Backing up mtd${i} (${NAME})..."
    dd if="/dev/mtd${i}ro" of="/mnt/usb/mtd${i}_${NAME}.bin"
    i=$((i + 1))
done
cp /proc/mtd /mnt/usb/proc_mtd.txt
sync && umount /mnt/usb

reboot

Wait 2–3 minutes. All LEDs will turn off, then blink, then stabilize. This is normal.

# Monitor from your PC:
while ! ping -c1 -W1 192.168.1.1 &>/dev/null; do echo "Waiting..."; sleep 2; done; echo "Router is up!"

  1. Click "Adjust UBI Layout" if it says "NOT ADJUSTED"
  2. Upload the 25.12.4 sysupgrade image, uncheck "Keep settings", and click Flash
  3. Wait several minutes — do NOT power off the router
  4. After reboot, access http://192.168.1.1 → you should see LuCI. Login: root, password: empty.

Troubleshooting

SSH: Connection refused
Verify Remote Assistance is enabled. Check your PC has an IP in the 192.168.0.x range. Try restarting the router and waiting 1 minute.
SSH: "REMOTE HOST IDENTIFICATION HAS CHANGED"

Expected after flashing — the SSH server changed. Remove the old key:

ssh-keygen -R 192.168.0.1
ssh-keygen -R 192.168.1.1
SSH: "no matching host key / cipher / kex"

Use the full command with legacy algorithm flags:

ssh -o KexAlgorithms=+diffie-hellman-group1-sha1 -o HostKeyAlgorithms=+ssh-rsa -c aes128-ctr root@192.168.1.1
Credentials don't work after downgrade/rollback
Do a hardware factory reset: hold the RESET button with a pin for 10 seconds. The router will ask you to create new credentials. Do not guess — you'll get locked out.

Revert to Stock Firmware

The restore command depends on how your backup was made. Using the wrong command (ubiformat vs mtd write) can destroy the NAND bad block table and permanently brick the router. Consult the MTD backup documentation before restoring.

Part 2
Minimal configuration via the GUI (LuCI)

With OpenWrt running and LuCI at http://192.168.1.1, this is the only thing I touch. Anything I don't mention is fine on its defaults. No SSH — everything through the web UI.

1. Password

Log in to LuCI as root and change the router password.

2. Firmware online checking → off

Turn off the online firmware check.

3. Firewall: WAN → DROP

Network → Firewall → Zones → the wan zone → Input: drop (it ships as reject).

4. Kill the ping

Network → Firewall → Traffic Rules → Allow-Ping → disable.

5. Hardware flow offloading

This one is not a traffic rule — it's a single checkbox. Network → Firewall → General Settings → under Routing/NAT Offloading tick Software flow offloading and then Hardware flow offloading (the hardware option only becomes available once software is on).

Software offloading puts established connections on a kernel fastpath, but the CPU still moves the packets. Hardware offloading hands them to the MT7621's packet engine (PPE) instead — same throughput, far less CPU. On this router both land around the same speed (~600 Mbps here, vs ~100 with no offloading), so hardware wins on efficiency. Two caveats, neither relevant to this setup: it doesn't accelerate WireGuard (the CPU still encrypts the tunnel), and it's incompatible with SQM/QoS.

6. Disable IPv6

We won't use IPv6, so remove it in two places.

Remove the WAN IPv6 interface

Network → Interfaces → delete the wan6 interface (the IPv6 one on WAN). We don't use it.

Turn off IPv6 on the LAN

Network → Interfaces → LAN → Edit → DHCP Server → IPv6 Settings:

RA-Service        disabled
DHCPv6-Service    disabled

With wan6 gone and RA / DHCPv6 disabled, the LAN stops handing out IPv6 addresses and the router runs IPv4-only.

7. DNS over HTTPS

System → Software → Update lists → install luci-app-https-dns-proxy. Installing it is enough: the router's DNS now leaves encrypted to Cloudflare.

Make it exclusive (stop the plaintext leak to your ISP)

By default the WAN still injects your ISP's plaintext DNS, so some queries leak unencrypted. Turn that off: Network → Interfaces → WAN → Edit → Advanced Settings → untick Use DNS servers advertised by peer. Now the router only forwards to the encrypted proxy.

8. AdBlock

Install luci-app-adblock-fast → enable the service → pick Hagezi Pro (first on the list).

To make adblock-fast run faster, also install these packages from System → Software: gawk, grep, sed and coreutils-sort.

9. DDNS — needed by WireGuard

Install luci-app-ddns. In Services → Dynamic DNS:

name              myddns
service provider  duckdns.org
lookup hostname   YOURNAME.duckdns.org
domain            YOURNAME
username          YOURNAME.duckdns.org
password          <your duckdns token>
HTTPS             on

Pick duckdns.org from the provider list (don't use custom). In domain put just your subdomain. LuCI won't accept an empty username, so repeat the hostname — duckdns ignores it.

10. WireGuard

Install luci-proto-wireguard. Network → Interfaces → Add new interface:

Name         wg0
Protocol     WireGuard VPN
Listen Port  53320
IP address   10.8.0.1/24

Hit Generate a new key pair for wg0 once (only here, never again). 53320 is just an example — any free UDP port works.

Traffic Rule — DNS for the peers

name         Allow-VPN-DNS
source       vpn
destination  Device (input)
protocol     TCP + UDP
port         53

Traffic Rule — open the WG port from outside

name         Allow-WireGuard
source       wan
destination  Device (input)
protocol     UDP
port         53320

The vpn zone

Firewall → Zones. Peers reach the internet but can't see the LAN:

name                       vpn
input                      drop
output                     accept
intra-zone forward         reject
ipv4 masquerading          on
mss clamping               on
covered networks           wg0
allow forward to dest      wan
allow forward from source  (empty)

Peer — one per device

name                   phone1
Allowed IPs            10.8.0.2/32
endpoint host          (empty)
endpoint port          (empty)
Persistent Keep Alive  25

Generate a key pair and a preshared key for the peer only (not wg0). The next device is 10.8.0.3/32 — always /32. Keep Alive 25 ends up in the QR, so you don't touch the phone app.

Generate configuration → QR

Scan the QR with the phone app. Mind the DNS:

DNS Servers   10.8.0.1

Use 10.8.0.1 (the tunnel IP) for DNS, not 192.168.1.1.

11. NTP with NTS

Install luci-app-chrony and chrony-nts. Build a server:

server   time.cloudflare.com
iburst   on
nts      on

Delete the default pool. Then go to System → Startup and disable sysntpd.
